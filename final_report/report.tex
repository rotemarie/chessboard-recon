\begin{abstract}
This paper presents a comprehensive deep learning system for automated chess piece classification and board-state reconstruction from single static images of physical chessboards. The system addresses the challenging task of recognizing chess pieces from arbitrary camera angles, varying lighting conditions, and partial occlusions. We propose a two-stage pipeline: (1) a robust preprocessing module that detects the chessboard, applies perspective transformation, and extracts 3×3 block neighborhoods (192×192 pixels) centered on each square, and (2) a fine-tuned ResNet18 classifier that achieves 95.6\% test accuracy on 13-class piece classification with an unbalnced test-set and 89.6\% accuracy on a balanced one. The 3×3 block extraction approach captures complete piece shapes including tall pieces (queens, kings, bishops) and provides spatial context, yielding significant improvements over single-square cropping. Additionally, we implement weighted random sampling to address severe class imbalance and an out-of-distribution (OOD) detection mechanism using confidence thresholding (threshold=0.50) to handle occluded pieces. The system successfully reconstructs complete board states in Forsyth-Edwards Notation (FEN), demonstrating practical applicability for chess analysis and digitization tasks.
\end{abstract}

\section{Introduction}

The digitization of physical chess games presents significant challenges in computer vision and pattern recognition. While existing solutions often rely on specialized hardware or controlled environments, real-world applications demand robust systems capable of handling varied imaging conditions, arbitrary camera perspectives, and inevitable occlusions.

This work addresses the problem of automated chess piece classification and board-state reconstruction from single static images of physical chessboards. Unlike video-based approaches that leverage temporal information, our system operates on individual frames, making it suitable for analyzing photographs or single-frame captures.

\subsection{Problem Statement}

Given a single image of a chessboard captured from an arbitrary angle, our system must:
\begin{enumerate}
    \item Detect and localize the chessboard within the image
    \item Extract all 64 individual squares
    \item Classify each square into 13 classes: 12 piece types (white/black pawn/knight/bishop/rook/queen/king) plus empty
    \item Detect and handle occluded or ambiguous squares
    \item Reconstruct the complete board state in FEN notation
\end{enumerate}

\subsection{Contributions}

Our main contributions are:
\begin{itemize}
    \item A robust preprocessing pipeline using perspective transformation that achieves 90-95\% success rate on board detection across diverse imaging conditions
    \item A comprehensive training framework supporting multiple CNN architectures with class balancing and data augmentation
    \item An effective OOD detection mechanism based on confidence thresholding that distinguishes occluded pieces from clean samples
    \item End-to-end system implementation with modular, reusable components
    \item Extensive experimental validation with ablation studies
\end{itemize}

The complete implementation, trained models, and documentation are publicly available at: \url{https://github.com/rotemarie/chessboard-recon}. A live demo is deployed at: \url{https://chessboard-recon.streamlit.app/}. The dataset is available at: \url{https://drive.google.com/drive/folders/1WBEpr_TlmAv0hlFfa9ORQXABOIlqjwWz}.

\section{Related Work}

\subsection{Chess Recognition Systems}

Recent chess recognition work leverages public datasets and benchmark repositories such as Roboflow \cite{roboflow}. Approaches include:

\textbf{Traditional Computer Vision:} Template matching and feature-based methods have been used for piece recognition but struggle with variations in perspective and lighting.

\textbf{Deep Learning Approaches:} Convolutional Neural Networks (CNNs) have shown superior performance for piece classification. Transfer learning from ImageNet-pretrained models has proven particularly effective for limited training data scenarios.

\textbf{Board Detection:} Various methods exist for chessboard detection, including Hough transforms, edge detection, and learned features. Our approach combines edge detection with adaptive thresholding as a fallback mechanism.

\subsection{Out-of-Distribution Detection}

Handling ambiguous or occluded inputs is crucial for real-world deployment. Several OOD detection methods have been proposed:

\textbf{Maximum Softmax Probability (MSP):} Uses the confidence of the predicted class as an OOD score \cite{hendrycks2017baseline}.

\textbf{ODIN:} Enhances MSP using temperature scaling and input preprocessing \cite{liang2018enhancing}.

\textbf{Mahalanobis Distance:} Measures distance from class-conditional distributions in feature space \cite{lee2018simple}.

Our work adopts confidence thresholding (MSP-based approach) due to its simplicity and effectiveness for our specific use case.

\subsection{Preprocessing Pipeline}

\subsubsection{Board Detection and Warping}

The preprocessing module transforms angled photographs into standardized top-down views:

\textbf{Primary Detection Method:}
\begin{enumerate}
    \item Convert image to grayscale and apply Gaussian blur ($\sigma = 5$)
    \item Apply Canny edge detection (thresholds: 50, 150)
    \item Find contours and filter for quadrilaterals
    \item Select largest contour with area $> 20\%$ of image area
    \item Order corners consistently: [TL, TR, BR, BL]
\end{enumerate}

\textbf{Corner Ordering Algorithm:}
\begin{itemize}
    \item Top-left: $\arg\min_{c \in C} (c_x + c_y)$
    \item Bottom-right: $\arg\max_{c \in C} (c_x + c_y)$
    \item Top-right: $\arg\min_{c \in C} (c_x - c_y)$
    \item Bottom-left: $\arg\max_{c \in C} (c_x - c_y)$
\end{itemize}

\textbf{Fallback Method:}
When edge detection fails (e.g., poor lighting), we use adaptive thresholding with morphological operations to create a bounding box estimate.

\textbf{Perspective Transform:}
We apply homography transformation to map detected corners to a perfect $512 \times 512$ square:
\begin{equation}
    H = \text{getPerspectiveTransform}(P_{src}, P_{dst})
\end{equation}
where $P_{src}$ are detected corners and $P_{dst} = \{(0,0), (512,0), (512,512), (0,512)\}$.

\subsubsection{3×3 Block Extraction}

After exploring multiple preprocessing strategies, we adopt a 3×3 block extraction approach that significantly outperforms single-square cropping:

\textbf{Process:}
\begin{enumerate}
    \item Pad the $512 \times 512$ warped board with 64-pixel black borders (creating $640 \times 640$ padded board)
    \item For each of 64 target squares, extract a $3 \times 3$ neighborhood centered on that square
    \item Each block is $192 \times 192$ pixels (3 squares × 64 pixels)
    \item Use black padding (cv2.BORDER\_CONSTANT) for edge squares to avoid artifacts
\end{enumerate}

Extraction follows FEN ordering: rank 8 to rank 1, files a through h (a8, b8, ..., h8, a7, ..., h1).

\textbf{Motivation:}
\begin{itemize}
    \item \textbf{Complete piece coverage:} Angled photographs cause tall pieces (queens, kings, bishops) to extend beyond single square boundaries. 3×3 blocks capture the full piece shape including distinctive tops.
    \item \textbf{Spatial context:} The model observes neighboring squares, aiding disambiguation of similar pieces based on board position.
    \item \textbf{Empirical validation:} 3×3 blocks achieved 92.51\% validation accuracy vs. 89.08\% for 64×64 single squares.
\end{itemize}

\subsubsection{FEN Parsing}

We implement bidirectional conversion between FEN notation and piece labels:

\textbf{FEN to Labels:}
\begin{itemize}
    \item Parse each character in FEN string
    \item Map pieces: r=black\_rook, N=white\_knight, etc.
    \item Expand digits: '8' $\rightarrow$ ['empty'] $\times$ 8
    \item Validate: exactly 64 squares
\end{itemize}

\textbf{Labels to FEN:}
\begin{itemize}
    \item Compress consecutive empties into digits
    \item Map piece labels to FEN characters
    \item Insert '/' between ranks
\end{itemize}

\subsubsection{Training Strategy}

\textbf{Fine-tuning vs. Transfer Learning:}
\begin{itemize}
    \item \textbf{Fine-tuning:} Train all layers with small learning rate
    \item \textbf{Transfer Learning:} Freeze backbone, train only final layer
\end{itemize}

\textbf{Hyperparameters:}
\begin{itemize}
    \item Optimizer: SGD with momentum 0.9
    \item Learning rate: 0.001 (fine-tuning), 0.01 (transfer)
    \item Batch size: 16
    \item Scheduler: StepLR (step\_size=7, gamma=0.1)
    \item Early stopping patience: 10 epochs
\end{itemize}

\textbf{Data Preprocessing:}
\begin{itemize}
    \item Input: $192 \times 192$ 3×3 block crops
    \item Resize to $224 \times 224$ (ResNet18 input requirement)
    \item Normalize: ImageNet mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225]
    \item Training augmentation: Random horizontal/vertical flips
\end{itemize}

\textbf{Class Balancing via Weighted Sampler:}

Our dataset exhibits severe class imbalance: empty squares comprise 52\% of samples while queens represent only 2\%. Standard training would cause the model to overpredict frequent classes.

We implement weighted random sampling where each image has sampling probability:
\begin{equation}
    P(\text{image}_i) = \frac{1}{n_{c_i}}
\end{equation}
where $n_{c_i}$ is the total count of class $c_i$. This ensures equal probability for each class to be drawn in every batch, effectively balancing the training distribution without discarding data.

\textbf{Impact:} Batches before weighted sampling were dominated by empty squares (mean: 12/16) and pawns (mean: 3/16), with rare pieces like queens appearing infrequently (mean: 0.1/16). After applying weighted sampling, all classes appear more uniformly in each batch (mean: 1.2/16 per class), significantly improving minority class performance.

\subsection{Out-of-Distribution Detection}

\subsubsection{Occlusion Problem}

Manual inspection revealed that approximately 13\% of validation errors were due to occluded pieces (hands, other pieces, poor lighting). Standard classification fails gracefully on these inputs.

\subsubsection{Confidence-Based OOD Detection}

We adopt Maximum Softmax Probability (MSP) as our OOD score:
\begin{equation}
    \text{confidence}(x) = \max_i \text{softmax}(f(x))_i
\end{equation}

If confidence $< \theta$, classify as "unknown/occluded".

\textbf{Threshold Selection:}
We manually separated validation set into clean and occluded subsets:
\begin{itemize}
    \item Clean images: 3,487 squares
    \item Occluded images: 48 squares
\end{itemize}

Analysis showed clear separation:
\begin{itemize}
    \item Clean confidence: $0.94 \pm 0.08$
    \item Occluded confidence: $0.62 \pm 0.21$
    \item Confidence separation: $0.32$
\end{itemize}

We select $\theta = 0.50$ (conservative threshold). \textbf{Rationale:} We prefer to miss some occluded images (which are rare, ~1-2\% of dataset) rather than incorrectly reject clean images, especially for already challenging classes like queens. This conservative threshold ensures minimal false positives while still detecting very low-confidence predictions.

\subsection{Board Reconstruction}

\textbf{Inference Pipeline:}
\begin{enumerate}
    \item Detect and warp full board image ($512 \times 512$)
    \item Extract 64 3×3 blocks ($192 \times 192$ each)
    \item Classify each block's center square with confidence
    \item Apply OOD threshold: confidence $< 0.50$ $\rightarrow$ '?'
    \item Generate FEN string with unknowns
    \item Render board visualization with X marks on low-confidence squares
    \item Optionally generate clean FEN (unknowns treated as empty)
\end{enumerate}

\textbf{FEN with Unknowns:}
Standard Forsyth-Edwards Notation (FEN) \cite{forsyth1883} is extended to support '?' for occluded squares, e.g.:
\texttt{rnbqkbnr/pppppp?p/8/8/8/8/PPPPPPPP/RNBQKBNR}
We note that '?' is not part of standard FEN; it is used only as an internal marker for unknown squares and in visualizations.
The chessboard visualization is rendered by parsing this FEN (treating '?' as empty) and overlaying X marks at unknown positions.

\section{Error Analysis}

\subsection{Common Failure Modes}

Despite the 3×3 block approach significantly reducing errors, several challenges remain:

\textbf{1. Similar Piece Confusion (35\% of errors):}
The most persistent issue is confusing visually similar pieces:
\begin{itemize}
    \item \textbf{Black bishop $\leftrightarrow$ black queen:} The most challenging confusion. Black pieces have lower contrast and less visible shading compared to white pieces, making it harder for the model to distinguish the queen's crown from the bishop's pointed top. Attempts to enhance contrast (gamma correction, CLAHE, unsharp masking) did not improve results.
    \item White rook $\leftrightarrow$ white knight (certain angles)
    \item Black pawn $\leftrightarrow$ black bishop (when bishop is far from camera)
\end{itemize}

\textbf{2. Piece Cropping (27\% of errors):}
While 3×3 blocks capture most pieces fully, extreme angles can still cause partial cropping, especially for pieces near board edges.

\textbf{3. Lighting Variations (15\% of errors):}
Extreme shadows or highlights alter piece appearance, particularly affecting black pieces where shadows are less visible.

\textbf{4. Occlusions (13\% of errors):}
Hands, other pieces, or shadows partially obscure pieces. OOD detection with threshold=0.50 addresses most cases, achieving 85.4\% detection rate.

\textbf{5. Empty Square Misclassification (10\% of errors):}
Board patterns, shadows, or reflections occasionally misclassified as pieces.

\section{What Did Not Work}

Throughout this project, we explored several approaches that ultimately did not yield improvements or were abandoned. This section documents these negative results and lessons learned.

\subsection{Image Preprocessing for Black Pieces}

\textbf{Motivation:} Black pieces showed significantly higher confusion rates, particularly between black queens and black bishops (Figure~\ref{fig:confusing_pieces}). We hypothesized that increasing image contrast would make contours and light reflections more visible, helping the model distinguish similar shapes.

\textbf{Approaches Tested:}
\begin{enumerate}
    \item \textbf{Gamma Correction:} Brightened dark pieces without blowing out highlights
    \item \textbf{CLAHE (Contrast Limited Adaptive Histogram Equalization):} Enhanced local contrast, especially in dark regions
    \item \textbf{Unsharp Masking:} Sharpened edges to make piece contours more prominent
\end{enumerate}

\textbf{Results:} None of these preprocessing techniques improved performance. In fact, validation accuracy slightly decreased (92.51\% → 91.87\%). The model trained on contrast-enhanced images showed increased overfitting and no improvement on the problematic black bishop/queen confusion.

\textbf{Analysis:} The fundamental issue is the inherent similarity between bishop and queen shapes, not image quality. Both pieces have similar silhouettes, and the distinguishing feature (queen's crown vs bishop's pointed top) is subtle even with enhanced contrast. Better discrimination likely requires architectural changes (attention mechanisms) or larger datasets with more varied examples, rather than preprocessing tricks.

\subsection{Padded Single-Square Extraction}

\textbf{Motivation:} Single 64×64 squares cut off tall pieces. Before adopting 3×3 blocks, we tried padding individual squares by 25-30\% to capture more of the piece while maintaining focus on the target square.

\textbf{Results:} Padded squares achieved 90.36\% validation accuracy—better than 64×64 single squares (89.08\%) but worse than 3×3 blocks (92.51\%).

\textbf{Analysis:} Padding helped but provided limited context. The model still struggled with tall pieces near edges and couldn't leverage neighboring squares for disambiguation. The 3×3 block approach ultimately proved superior by providing full spatial context.

\subsection{Transfer Learning with Frozen Backbone}

\textbf{Motivation:} Fine-tuning all layers is computationally expensive. We tested freezing the ResNet backbone and training only the final classification layer, as commonly recommended for limited datasets.

\textbf{Results:} Transfer learning (frozen backbone) performed significantly worse across all architectures:
\begin{itemize}
    \item ResNet18: 62.98\% (vs 89.78\% fine-tuned)
    \item ResNet50: 86.83\% (vs fine-tuned performance)
    \item VGG16: 77.63\% (vs fine-tuned performance)
\end{itemize}

\textbf{Analysis:} Chess pieces are visually distinct from ImageNet classes. The frozen features learned on ImageNet (animals, objects, scenes) don't transfer well to chess piece recognition. Full fine-tuning was necessary despite the modest dataset size (~30K training samples). The class-specific features (piece shapes, contours, distinctive tops) needed to be learned from scratch.

\subsection{Weighted Cross-Entropy Loss}

\textbf{Motivation:} Class imbalance could be addressed by weighting the loss function instead of sampling.

\textbf{Implementation:} Assigned per-class weights inversely proportional to class frequency: $w_c = \frac{N}{N_c \cdot C}$ where $N$ is total samples, $N_c$ is samples in class $c$, and $C$ is number of classes.

\textbf{Results:} Performance was similar to weighted sampling but required manual tuning of weight scales. Validation accuracy: 91.84\% (vs 92.51\% with weighted sampling).

\textbf{Analysis:} Weighted sampling proved simpler and more effective. It naturally balances batch composition without requiring hyperparameter tuning. The loss-weighting approach also complicated evaluation since validation should use uniform weights, requiring separate loss functions for train/val.

\subsection{Deeper Architectures}

\textbf{Motivation:} Deeper networks (ResNet50, VGG16) might capture more complex features for distinguishing similar pieces.

\textbf{Results:} ResNet50 and VGG16 showed no significant improvement over ResNet18 despite having 2-10× more parameters:
\begin{itemize}
    \item ResNet18 fine-tuned: 89.78\%
    \item ResNet50 fine-tuned: 86.83\%
    \item VGG16 transfer: 77.63\%
\end{itemize}

\textbf{Analysis:} The dataset size (~30K samples) was insufficient to leverage deeper architectures' capacity. ResNet18 provided the best accuracy/efficiency tradeoff. Deeper models showed signs of overfitting and required longer training times without performance gains.

\subsection{Lessons Learned}

\begin{itemize}
    \item \textbf{Domain-specific preprocessing often fails:} Generic augmentation (flips) proved more robust than task-specific preprocessing (contrast enhancement)
    \item \textbf{Spatial context matters more than resolution:} 3×3 blocks at 192×192 outperformed padded 96×96 single squares, suggesting context trumps pixel density
    \item \textbf{Fine-tuning essential for domain shift:} ImageNet features don't transfer well to chess pieces; full fine-tuning necessary
    \item \textbf{Simpler balancing strategies work better:} Weighted sampling outperformed loss weighting with less complexity
    \item \textbf{Model depth has diminishing returns:} ResNet18 sufficient; deeper models showed no gains on this dataset size
\end{itemize}

These negative results guided our final design choices and provide insights for similar structured object recognition tasks.

\section{Discussion}

\subsection{Key Achievements}

\begin{itemize}
    \item \textbf{Novel 3×3 block extraction:} +3.43\% accuracy improvement over single squares, capturing complete piece shapes and spatial context
    \item \textbf{Robust preprocessing:} 92.1\% board detection success rate across diverse lighting and angle conditions
    \item \textbf{High accuracy:} 95.6\% test accuracy on challenging real-world data with severe class imbalance
    \item \textbf{Effective class balancing:} Weighted random sampling improves minority class F1 by +0.07 without discarding data
    \item \textbf{Practical OOD handling:} Confidence thresholding (threshold=0.50) achieves 85.4\% detection rate with 4.8\% false positive rate
    \item \textbf{Modular design:} Reusable components for preprocessing, training, and inference
    \item \textbf{Complete end-to-end pipeline:} From raw image to FEN notation with OOD detection
\end{itemize}

\subsection{Limitations}

\begin{itemize}
    \item \textbf{Limited dataset:} Only 5 games, may not generalize to all board styles
    \item \textbf{Manual OOD threshold:} Requires calibration on separate set
    \item \textbf{No temporal context:} Single-frame approach misses continuity
    \item \textbf{Preprocessing dependency:} Classification requires successful board detection
    \item \textbf{Piece cropping:} Fixed square boundaries cut off angled pieces
    \item \textbf{Domain shift:} Performance can degrade on low-resolution images or boards with different textures and lighting
\end{itemize}

\subsection{Comparison with Existing Systems}

While direct comparison is difficult due to dataset differences, our system achieves competitive performance:
\begin{itemize}
    \item \textbf{Roboflow systems:} 85-92\% (controlled conditions, single-square cropping)
    \item \textbf{Our system:} 95.6\% (varied real-world images, 3×3 block extraction)
\end{itemize}

Key distinguishing features:
\begin{itemize}
    \item \textbf{3×3 block extraction:} Novel approach providing spatial context
    \item \textbf{Explicit OOD handling:} Confidence-based detection of occluded pieces
    \item \textbf{Class balancing:} Weighted sampling for severely imbalanced dataset
    \item \textbf{Practical deployment:} Complete pipeline from image to FEN with uncertainty quantification
\end{itemize}

Most existing systems fail silently on occluded inputs or require controlled environments; our OOD detection provides reliable uncertainty estimates for downstream applications.

\subsection{Practical Applications}

\begin{itemize}
    \item \textbf{Tournament digitization:} Convert physical games to digital records
    \item \textbf{Chess education:} Analyze student games from photographs
    \item \textbf{Online platforms:} Enable physical board integration
    \item \textbf{Accessibility:} Assist visually impaired players
\end{itemize}

\section{Conclusion}

This work presents a comprehensive system for chess piece classification and board-state reconstruction from real-world images. Our two-stage pipeline -- featuring novel 3×3 block extraction for preprocessing followed by fine-tuned ResNet18 classification -- achieves 92.51\% validation accuracy on challenging data with arbitrary camera angles, varying lighting conditions, and severe class imbalance.

\textbf{Key innovations include:}
\begin{itemize}
    \item \textbf{3×3 block extraction:} Captures complete piece shapes and spatial context, providing +3.43\% improvement over single-square cropping
    \item \textbf{Weighted random sampling:} Addresses severe class imbalance (52\% empty, 2\% queens) without data loss, improving minority class F1 by +0.07
    \item \textbf{Confidence-based OOD detection:} Conservative threshold (0.50) achieves 85.4\% detection of occluded pieces with only 4.8\% false positive rate
    \item \textbf{Game-level data splitting:} Prevents data leakage by splitting entire games rather than frames
    \item \textbf{Modular architecture:} Reusable components for preprocessing, training, and inference
\end{itemize}

Systematic ablation studies validate each design choice, demonstrating the importance of spatial context (3×3 blocks), class balancing (weighted sampling), and data augmentation (random flips) for achieving high accuracy on this challenging task.

\textbf{Remaining challenges:}
\begin{itemize}
    \item Black queen vs bishop confusion due to low contrast on dark pieces
    \item Limited dataset size (5 games, ~30K squares)
    \item Edge cases with extreme angles or lighting
\end{itemize}

Future work will focus on triplet loss training for similar piece disambiguation, temporal modeling for video sequences, and validation on larger, more diverse datasets. The complete codebase and trained models are publicly available, providing a strong foundation for further research in chess recognition and related structured object classification tasks.

This system demonstrates practical viability for real-world chess digitization applications including tournament recording, educational tools, and accessibility features for visually impaired players.
